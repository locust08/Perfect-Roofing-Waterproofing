# Foundation Quality Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Improve accessibility, search-engine foundations, redirect behavior, and response headers without altering the site's design, routes, content, or static-asset architecture.

**Architecture:** Retain Astro static generation and Cloudflare Workers Static Assets. Use semantic Astro markup and conditional metadata while the production domain is unconfirmed. Use native Cloudflare `_redirects` and `_headers` files in `public/`, which Astro copies into `dist` at build time.

**Tech Stack:** Astro 7 static output, Cloudflare Workers Static Assets, Webflow CSS/JS, jQuery.

**Spec:** User request in this task.

## Global Constraints

- Work from `revamp-foundation` on `fix/foundation-quality`.
- Do not redesign the UI, change service content, add a backend/form submission service, or connect a production domain.
- Keep the static Astro plus Cloudflare Workers Static Assets architecture.
- Preserve all existing redirect destinations.
- Do not add a false canonical or sitemap hostname while the production domain is TBC.

## Review Focus

- Direct keyboard navigation reaches and visibly focuses the mobile-nav trigger, service link, FAQ controls, and contact controls.
- Contact inputs have programmatic labels that retain their existing visual presentation.
- Legacy redirect paths return HTTP redirects rather than HTML meta refresh responses.
- Response headers do not block the existing Webflow, jQuery, Google Webfont, font, image, or embedded external content flows.
- Every emitted HTML page has a single H1, and no generated local asset reference is missing.

### Task 2: SEO crawler files and Cloudflare-native policy files

**Files:**
- Modify: `public/robots.txt`
- Modify: `public/sitemap.xml`
- Create: `public/_redirects`
- Create: `public/_headers`

**Interfaces:**
- Consumes: static paths generated by Astro and the three legacy redirect destinations.
- Produces: deployable static-asset redirect and header rules.

- [ ] **Step 1: Retire the old hostname from crawler files**

Keep robots rules but remove the old sitemap declaration. Keep a valid empty sitemap endpoint while production hostname is TBC, rather than publishing invented or staging canonical URLs.

- [ ] **Step 2: Move each legacy page redirect into `_redirects`**

Read the existing destination from every redirect page, then add its exact source path and destination as a `301` rule, including the trailing-slash variant. Do not add redirect rules for any other route.

- [ ] **Step 3: Add conservative `_headers` rules**

Apply `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `X-Frame-Options`, and a CSP limited to `frame-ancestors`, `base-uri`, and `object-src` so external scripts, fonts, images, and embeds are unrestricted by this policy.

- [ ] **Step 4: Verify static policy files are built**

Run: `npm run build; Test-Path dist/_headers; Test-Path dist/_redirects; Get-Content dist/_redirects`

Expected: both policy files exist in `dist` and list only the verified redirect paths.
